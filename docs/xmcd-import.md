# Импорт файлов Mathcad 15 (.xmcd)

xmath умеет открывать рабочие листы Mathcad 15, сохранённые в XML-формате `.xmcd`
(пространства имён `worksheet30` и `math30`). Импорт реализован в модуле
`xmath_core::xmcd` (`import_xmcd`, `import_xmcd_file`).

Командная строка:

```
xmath-cli sheet.xmcd                       # импорт, вычисление, вывод; предупреждения в stderr
xmath-cli sheet.xmcd --convert sheet.xmath # дополнительно сохранить в формате xmath (JSON)
```

Формат определяется по расширению `.xmcd` либо по заголовку `<?xml ... worksheet`.
Сжатые файлы `.xmcdz` не поддерживаются (распакуйте их или пересохраните как `.xmcd`).

## Комментарии xmath

Файл, записанный самим xmath, содержит комментарии `<!--xmath:region {json}-->` (график, 3D-график,
текст, ширина которого не фиксирована) и `<!--xmath:worksheet {json}-->` (формат результата, формат
графиков по умолчанию, страница). Импорт читает их: из `region` берётся вся область, если элемент
графика Mathcad (выражения, пределы осей) или текст не менялись после сохранения; иначе действует то, что записано
в самом файле. Для файлов Mathcad комментариев нет, и импорт идёт как описано ниже.

## Принципы

* Импорт никогда не завершается паникой. Некорректный XML возвращает ошибку.
* Ничего не пропадает молча: всё, что нельзя перенести, превращается в
  текстовую область с приблизительной записью содержимого и добавляется в список
  предупреждений.
* Каждая сгенерированная математическая область проверяется разбором
  `parse_statement`; если проверка не прошла, область становится текстовой.
* Координаты Mathcad (пункты) умножаются на 96/72, чтобы расположение выглядело
  привычно при 96 dpi. Относительное расположение сохраняется.
* Сохранённые в файле результаты вычислений (`<result>`) не используются при показе, все
  значения пересчитываются; они нужны только для проверки совместимости (`--check`, ниже).
* Порядок вычисления, как в Mathcad, определяется «якорем» области (базовая линия оператора
  `:=`/`=`, атрибуты `align-x`/`align-y`), а не левым верхним углом: сначала по `y`, затем по `x`.
  Смещение якоря хранится в `Region.anchor`.
* Обёртки `<ml:provenance>` (ссылки на исходный документ) прозрачно снимаются.
* Области `<area>` разворачиваются во вложенные области; `pageBreak` пропускается.

## Поддерживается

Математика:

* определения `:=` (`ml:define`), глобальные `≡` (`ml:globalDefine`);
* определения функций `f(x, y) := ...`, индексированные определения `v[i] := ...`;
* вычисления `=` (`ml:eval`), в том числе с единицей вывода (`ml:unitOverride`);
* идентификаторы, греческие буквы (Unicode), литеральные индексы
  (`атрибут subscript` -> `x.max`);
* числа, мнимые числа, строки;
* операции: `+ - * / ^`, унарный минус, `sqrt`, `nthRoot`, `|x|`, `n!`,
  сравнения, `and`, `or`, `¬`, скобки;
* вызовы функций (одиночный аргумент или `ml:sequence`);
* индексация `v[i]`, `M[i, j]`;
* матрицы и векторы (элементы в файле хранятся по столбцам, при импорте
  корректно переставляются);
* диапазоны `0..10` и `0, 0.5..10`;
* `transpose`;
* интеграл, производная (в том числе порядка n), сумма, произведение,
  сумма и произведение по диапазону -> `integrate`, `diff`, `sum`, `prod`;
* единицы измерения (как идентификаторы; имена должны совпадать с поддерживаемыми
  в xmath).

Программы (полностью, включая Mathcad-семантику области видимости):

* операторы `x ← e`, `v[i] ← e`, `M⟨j⟩ ← e` (столбец матрицы), `[a; b] ← v` (вектор имён;
  вариант `[a⟨0⟩; b⟨1⟩] ← …` разворачивается в отдельные присваивания), `f(x) ← e`
  (локальная функция), `if … otherwise`,
  `for`, `while`, `break`, `continue`, `return`, `on error` (`tryCatch`);
* присваивание как выражение: `X[(k ← 2)] := …`, `1/(i - 2) on error continue`,
  `f(x) := 1/x on error (return 0)`;
* программа внутри выражения (`(for i ∈ … { … }) == 3`), матрица из нескольких выражений в конце
  программы — значение-вектор (`{ j ← 0; [j; v[j]] }`);
* локальные переменные — как в Mathcad 13 и новее: имя, которому присваивают где-либо в
  программе, локально для всей программы; до первого присваивания оно равно 0, а справа от
  присваивания до первого присваивания видно значение листа; переменная цикла и параметры
  функции не затеняются;
* `Q1(x) := x^2` вместе с `Q1 ← Q1(j)` в программе — ошибка «функция ссылается на себя
  непоследовательно», как в Mathcad.

Прочее:

* текстовые области: абзацы, переносы строк, `b`, `i`, нижние и верхние индексы
  (`A_1`, `x^2`), встроенные формулы (в виде текста). Жирный шрифт, курсив,
  подчёркивание и размер применяются ко всей области, если ими отформатирован
  весь текст;
* графики XY из бинарного формата Mathcad (`docs/xmcd-plot-format.md`): выражения по осям X и
  Y, абсцисса для каждой трассы, пределы осей;
* рисунки (`picture`), а также графики, объекты OLE и компоненты, которые не удалось
  декодировать, импортируются как область-изображение (PNG, который сохранил Mathcad);
* настройки листа: `ORIGIN` (при значении, отличном от 0, сверху добавляется
  область `ORIGIN ≡ n`), число знаков после запятой, порог экспоненциальной
  записи.

## Не поддерживается (с предупреждением)

| Что | Как импортируется |
|-----|-------------------|
| Символьные вычисления (`→`, `ml:symEval`) | заменяются численным вычислением `=` |
| Векторизация (стрелка над выражением) | оператор отбрасывается |
| Неопределённый интеграл | текстовая область |
| Производная в точке, отличной от переменной дифференцирования | считается производная по переменной |
| Незаполненные плейсхолдеры `■` | текстовая область |
| Области других типов без картинки | текстовая область-заглушка |
| Графики, которые не удалось декодировать | изображение; без `rendering` — `[График не импортирован]` |
| Цвета/типы линий трасс, вторая ось Y, маркеры | не переносятся |
| Неизвестные элементы и операции | текстовая область с записью содержимого |
| Форматирование результатов по отдельным областям, колонтитулы, разрывы страниц, стили, гиперссылки, защита областей, свёрнутые области | игнорируются |
| Функции, отсутствующие в xmath | область импортируется как формула, но при вычислении даст ошибку |

Разметка Mathcad 15 не документирована официально, поэтому импорт опирается на
известную структуру файлов. Если ваш файл импортируется неверно, пришлите его
(или фрагмент) для доработки.

## Проверка совместимости: `xmath-cli --check`

```
xmath-cli --check файл.xmcd [файл2.xmcd ...] [-v] [--no-anchors]
```

Файл импортируется, вычисляется, и каждое значение сравнивается с результатом, который Mathcad
сохранил в `<result>` (относительный допуск 1e-6; единицы приводятся к СИ по `unitReference`,
значение в файле лежит в отображаемой единице). Для каждой области печатается
`OK` / `MISMATCH` / `NOT EVALUATED` / `SKIPPED` и сводка с частыми причинами. `--no-anchors`
отключает порядок по якорям (для сравнения «до/после»). Код возврата 1, если есть расхождения.
В ядре: `xmath_core::xmcd_check::check_import`, ожидаемые значения —
`ImportResult::expected`.

Сводка:

| Набор | OK | MISMATCH | NOT EVALUATED | SKIPPED |
|-------|----|----------|---------------|---------|
| lab4.xmcd, итог | 28 | 0 | 0 | 0 |
| корпус, по якорям (до доработок совместимости) | 479 | 69 | 263 | 2 |
| корпус, итог (704 файла) | 1331 | 103 | 607 | 133 |
| файлы с программами (98 из 103, остальные не успели по таймауту) | 331 | 42 | 220 | 33 |

Все 996 элементов `ml:program` в 103 файлах корпуса импортируются: ни одна область не остаётся
текстовой. Среди областей, содержимое которых — сама программа, расходится одна:
`{ for j ∈ 0..3 { Q1[j] ← Q1(j) }; Q1 }` в `mg_programming` (Mathcad 14 сохранил значение,
Mathcad 15 на этом листе ожидает ошибку). Остальные расхождения в этих файлах относятся к другим
областям (блоки решения, единицы, отсутствующие функции) либо к значениям, которые вычисляют
программы: `Pipeex` (3 — распределение расходов в параллельных трубах сходится к другому
решению), `newerr` и `mg_units` (Mathcad показал ошибку единиц, xmath вычислил значение),
`mg_programming` `ff2(1) = 3` (в файле сохранён результат Mathcad 12, сам лист описывает
поведение Mathcad 13+).

Исправленные причины:

* Программы: разбираются все конструкции Mathcad 15 (см. «Поддерживается»), включая статическую
  область видимости Mathcad 13+, присваивание столбца матрицы, локальные функции, присваивание как
  выражение и матрицу из нескольких операторов в конце программы как значение.
* Функции Mathcad 15, которых не было: `PolyLookup` (таблица 80 многогранников), `Floor`/`Ceil`/
  `Trunc`/`Round` с порогом, `mag`, `phase`, `phasecor`, `makeri`, `DMS`, `Seed`, `setwindow`,
  `SIUnitsOf`, `stderr`, `Spear`, `Rank`, `dilog`, `Psi`, `Zeta`, `Ei`, `Si`, `Ci`, `FresnelC`,
  `FresnelS`, `hypergeom`, `mhyper`, `fhyper`; полные имена единиц СИ (`volt`, `ampere`, `newton`, …).
* Логические операторы как в Mathcad: `and`/`or` поэлементно на матрицах (минимум/максимум для
  изображений), `⇒`/`⇔`, `vectorize(¬P)`.
* Смешанные таблицы: литерал матрицы со строковой ячейкой (`DataSet := […, "2003 Aug 29", 0; …]`)
  сохраняет все ячейки; `rows`, `cols`, `length`, `submatrix`, `M[i, j]` и `M⟨j⟩` работают с такой
  таблицей, числовой срез снова становится матрицей.
* `loess`: Mathcad (как netlib loess с `surface = "interpolate"`) строит k-d-дерево (ячейки до
  `floor(n*span*0.2)` точек), считает локальную квадратичную подгонку (значение и наклон) только в вершинах
  и склеивает кубическими многочленами Эрмита; совпадение с сохранёнными значениями до 1e-13
  (`dd(950)`, `dd(1000)` в lab4).
* Показ значения у определений `v[i] := expr =` и `[a; b] := expr =`.
* Индексные определения по диапазону последовательны: `a[j + 1] := f(a[j])` видит уже
  вычисленные элементы.
* Деление вещественных чисел точное (`1/0.2 = 5`, раньше формула комплексного частного давала 8.9e-16).
* Неопределённое `i`/`j` равно мнимой единице.
* Порядок собственных значений несимметричной матрицы - порядок диагонали формы Шура (как LAPACK/Mathcad),
  у эрмитовых и симметричных - по возрастанию; порядок сопряжённых корней `polyroots`.
* Импорт `conjugate` (`conj`), `vectorSum` (`sum`), `xor`, `polyroots`.

Оставшиеся причины (корпус):

| Причина | Примерно |
|---------|----------|
| Блоки `Given`/`Find`/`Minerr`/`Maximize`/`Minimize` и определитель (другая ветка) | 70 |
| Переменные из внешних ссылок и файлов (`READFILE`, `<reference>`: `K.90`, `y_stat`, `a0`...) | 100+ |
| Случайные числа (`rnd`, `rnorm`, `rpois`...), значения не воспроизводимы | 30 |
| Функции сторонних библиотек (`FluidProp`, `HAProp`, `rp_hfp`...) | 15 |
| Знак собственных векторов (`eigenvecs`), порядок корней в LAPACK | 1 |
| Символьные вычисления (`limit`, `symEval`) | 10 |
| Плохо обусловленные системы (`lsolve`, расхождение 1e-5) | 1 |
