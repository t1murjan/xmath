# Формат графиков Mathcad 15 в `.xmcd` (результаты реверс-инжиниринга)

Область графика: `<region><plot disable-calc="false" item-idref="17"/><rendering item-idref="18"/></region>`.
`item-idref` указывает на `<binaryContent><item item-id="17" content-encoding="gzip">BASE64</item>`;
после base64 и gunzip получается проприетарная сериализация. `rendering` — PNG, который
Mathcad нарисовал сам (используется как запасной вариант). Декодер: `xmath_core::xmcd_plot`.

## Общая структура

Файл — набор записей, из которых нас интересует «дерево выражений»: после строки `tree`
(`04 'tree'`), константного заголовка `1b 00 00 00 00 00 32 00 00 00 0d 70 00 00 00 00 00`
идут узлы с номерами 6, 7, 8, … (последовательно). Узел:

```
номер  тег  класс(2, big-endian)  00 00  флаг  родитель  данные...
```

Тег — `32` в файлах старых версий Mathcad и `40 40` (два байта) в файлах Mathcad 15,
включая все штатные примеры из поставки.

* номер и родитель — «короткие» числа: значения < 0x40 в одном байте, большие — в двух:
  `0x40 | (v >> 8)`, `v & 0xff` (то есть узел 64 записан `40 40`);
* родитель 5 — корень;
* флаг: `0x40` (маска `0xC0`) — левый потомок, `0x80` — правый; младшие биты — служебные
  (листья `0x64/0x74/0xa4/0xb4…`);
* узлы идут в прямом порядке обхода (сначала левое поддерево), поэтому конец узла — это
  следующий номер с тегом `0x32` и правдоподобным заголовком;
* после последнего узла идёт хвост с форматированием (`graphData`, `axisFormat`, `trace2D`,
  `NumericalFormat`, `annotData`, …) — цвета и типы трасс, подписи осей и т. д. Не разобран.

## Листья

* класс `020f` — идентификатор или число; `5a0f` — строка; `000f` — пустое место (плейсхолдер);
* данные листа: `00 00 n  [01 n-1]  символы`, где `n-1` — число символов UTF-16LE, затем `00`.
  Для идентификатора `n, n-1, текст`; для числа в файлах из Mathcad 15 перед длиной стоит `01`
  (`n 01 n-1 текст`); в старых файлах числа записаны как идентификаторы — различаем по первому
  символу (цифра). Литеральный индекс записан точкой: `Q.Plant` (как у `id_name` в импортёре);
  `_` — обычный символ имени.

## Классы операций

| класс | значение | потомки |
|-------|----------|---------|
| `19c1` | график XY (корень) | Y-группа, X-группа (X может отсутствовать) |
| `9fc1` | пара/контейнер | 2 |
| `1340`, `1440` | обёртки (один потомок `19c1`) | 1 |
| `0ac3` | запятая (список), левоассоциативно | 2 |
| `12ce` | вызов функции | имя (лист), `8e70` |
| `8e70` | скобки / список аргументов | 1 (аргументы через `0ac3`) |
| `06ca` | умножение | 2 |
| `07fb`, `07cb` | деление | 2 |
| `05cc`, `05fc` | степень | 2 |
| `89c7` / `88c7` | сложение / вычитание | 2 |
| `954b` | унарный минус | 1 |
| `9a7b` | квадратный корень | 1 |
| `04fd` | индексация `v[i]` | 2 |
| `34fd` | столбец матрицы `M<n>` | 2 |

Неизвестные классы (например `e570`) приводят к отказу декодера; график тогда импортируется
как рисунок из `rendering`.

## Оси

```
ось  := 9fc1( 9fc1( 9fc1(max, min), 9fc1(маркеры...) ), ВЫРАЖЕНИЯ )
график XY := 19c1( 9fc1(ось_Y, вторая_ось), ось_X )
график без оси X (QuickPlot) := ось_Y  (корень 9fc1)
```

* `max`/`min` — выражения-пределы оси (пусто — авто). Порядок: сначала максимум, затем минимум
  (проверено по рисункам). `0,0` во второй оси — значения по умолчанию;
* `ВЫРАЖЕНИЯ` — список через `0ac3`: для Y — трассы, для X — абсциссы. Пары (x_i, y_i)
  соответствуют друг другу; одна абсцисса относится ко всем трассам;
* вторая ось Y и маркеры в импорте не используются.

## Что извлекается

Выражения по X и Y (как `Expr`), пределы осей (числовые константы), число трасс.
Проверено на 216 графиках (92 файла): все дерево-разборы проходят, в них встречаются
перечисленные выше классы. Не декодируется: цвет/тип/толщина линий трасс, подписи, маркеры,
вторая ось Y, 3D, полярные и контурные графики (в корпусе не встретились).


## Полярные и 3D-графики; таблица трасс

В корпусе (96 файлов, 216 графиков, включая пользовательские) все графики — X-Y: в их хвосте
присутствуют только записи `graphData`, `axisFormat`, `trace2D`, `NumericalFormat`. Полярных,
поверхностных и контурных графиков в корпусе нет, поэтому их разбор не реализован: такие области
(неизвестный корневой класс узла) возвращают `Err` и импортируются как рисунок из `rendering`.

Запись `trace2D` содержит таблицу из 16 трасс (маркер `1f 01 10`), каждая запись — `1f 01 <i> 01
1b <тип линии> <R> <G> <B>`; тип линии 1 — сплошная, 2 — точки, 3 — штрихи, 4 — штрих-пунктир.
Таблица по умолчанию: красный/1, синий/2, зелёный/3, пурпурный/4, голубой/1, коричневый/2, чёрный/3,
красный/4, ... Изменённые трассы записаны вариантами (`1b 02 01 04 01`, `1e 03 05 01 01`), формат
которых однозначно не установлен, поэтому цвета и типы линий не импортируются (используются
значения по умолчанию xmath).

## Запись графиков (кодировщик)

`xmath_core::xmcd_plot_write` пишет то же, что читает декодер, в той же последовательности, что и Mathcad 15
(проверено сравнением байт дерева выражений с 193 реальными графиками корпуса: 165 совпадают, 28 других шапок;
тест `corpus_trees_are_reproduced_byte_for_byte`, `XMCD_CORPUS=каталог`).

```
шапка: 0c 00 00 00 01 00 00 00 53 00 00 00 0a 00 00 00 01 00 | 03 00 00 00 08 "eqRegion" | 05 .. 34 .. 09 "docRegion" |
       04 .. 39 .. 08 "mcObject" | .. 52 .. 01 00 | 02 .. 06 "shpBox" | .. 4c .. 07 "shpRect" | .. 4d 00 00 00
       прямоугольник области, пиксели 96 dpi: left top right bottom left top (6 × u32 LE) | 00 00 00 00 | номер области u32 | 01 00 00 00 |
       02 00 02 03 00 01 00 00 00 12 "docRegionAttribute" 01 .. 3a .. 0f .. (нули) 04 3a 22 .. (нули) 05 00 01 00 00 00 04 "tree"
дерево: 1b 00 00 00 00 00 32 00 00 00 0d 70 00 00 00 00 00, затем узлы, затем «номер следующего узла» (короткое число) 00
формат: 02 00 00 00 0f "d2_graph_format" … "graphData" … "axisFormat" ×3 … "trace2D" (16 записей) … "NumericalFormat" …
```

Правила узлов, найденные по корпусу (в дополнение к описанию выше):

* после данных операции с **одним** потомком (`954b`, `9a7b`, `8e70`, `1340`, `1440`) идёт один байт `00` до потомка;
* каждая операция после последнего потомка закрывается одним байтом `00` (у корня, а также у обёрток `1340/1440`, и
  у «настоящего» корня под ними закрытия нет); у произведения, набранного слитно (`2x`, `5 cm`), закрывающий байт равен `01`;
* у числового листа флаг имеет вид `0x34/0x36` (бит `0x02` не связан с целостью числа), у идентификатора `0x24`,
  у пустого места `0x02`; сторона потомка: `0x40` слева, `0x80` справа. Список через запятую встречается и
  лево-, и правоассоциативным;
* лист: `00 00 n` + (для числа `01`) + `n-1` + UTF-16LE + `00`;
* запись трассы `trace2D`: `1f 01 <i> 01 1b <тип 1..4> R G B` (для нулевой — `1f 01 10 00 01 1b …`); именно в этой форме
  кодировщик пишет цвет и тип линии. Остальное содержимое хвоста (флаги `axisFormat`: `4c`, `4e`, `0e`, `1e`, `5c` …) не
  расшифровано, пишется значениями по умолчанию, а полный формат хранится в комментарии `xmath:region`.
