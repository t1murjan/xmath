# Печать, PDF, экспорт в Mathcad, файлы и ссылки

## PDF и печать

* `Файл → Экспорт в PDF…`, `Предварительный просмотр`, `Печать…` (Ctrl+P), `Параметры страницы…`.
* Командная строка: `xmath-cli лист.xmath --pdf out.pdf`. MCP: инструмент `export_pdf {path, out}`.
* Страницы режутся по линиям разрыва, которые видны на полотне (кратны высоте области печати);
  область, которую пересекла бы линия, переносится на следующую страницу целиком.
* Формулы набираются как на экране (2D), текст — настоящий (встроенные подмножества шрифтов Arial /
  Liberation Sans и DejaVu Sans, его можно выделять и искать), графики и линии — векторные,
  рисунки — растровые.
* Параметры страницы (бумага A3/A4/A5/Letter/Legal, ориентация, поля в мм) хранятся в листе
  (`page` в `.xmath`, `pageModel` в `.xmcd`). По умолчанию A4, поля 5/11/5/11 мм (область печати
  примерно 756 × 1039 пикселей, как страница на полотне).
* Печать: временный PDF отправляется командой `lp` (Linux, принтер по умолчанию), если её нет —
  открывается программой просмотра (`xdg-open`; macOS `open`, Windows — программа по умолчанию).

Устройство: `xmath_gui::print::Sheet` раскладывает области (`layout`), `paginate` делит на страницы,
`paint_page` рисует страницу через `egui::Painter`. Предпросмотр рисует им же на экране; PDF
рисует в «безголовый» контекст egui, а `canvas::paint_shapes` переводит фигуры в вызовы трейта
`canvas::Canvas { line, polyline, fill_poly, text, image, circle, rect, clip }`, реализованного
в `pdf::PdfPage`. Любой новый вид графика, который рисуется через `Painter`, попадает в PDF
без дополнительной работы; можно и рисовать прямо в `Canvas`.

## Формат `.xmcd` — основной формат сохранения (Mathcad 15)

`Файл → Сохранить` (Ctrl+S) и `Сохранить как…` пишут `.xmcd` (первый фильтр и имя по умолчанию
`<имя>.xmcd`; путь без расширения получает `.xmcd`); `.xmath` остаётся вторым фильтром «Сохранить как…».
Лист, открытый из `.xmcd`, сохраняется в тот же файл; лист из `.xmath` — в `.xmath`. CLI:
`xmath-cli лист --export-xmcd out.xmcd`; MCP: `export_xmcd`, а также любые инструменты с путём `.xmcd`.

Пишется `worksheet30`/`math30`: определения, глобальные определения, вычисления с единицей вывода
(`unitOverride`), функции (`boundVars`), индексы, матрицы по столбцам, диапазоны, интегралы, производные,
суммы и произведения (`lambda` + `bounds`), программы, `vectorize`, `onError`, блоки решения, текст (многие пробелы —
`<sp count=…/>`), рисунки (PNG), ссылки, настройки результата и страницы. Для вычисляемых областей пишется
`<result>` (число, матрица по столбцам, комплексное, строка, `unitedValue` с базовыми единицами СИ), как
у Mathcad. Ссылка на `.xmath` записывается как `.xmcd` (с замечанием).

**Графики.** `xmath_core::xmcd_plot_write::encode_plot` — обратная операция к декодеру: пишет настоящий
элемент графика Mathcad (заголовок с прямоугольником области и номером, дерево выражений, номер
следующего узла, `d2_graph_format`: `graphData`, три `axisFormat`, таблица `trace2D` из 16 трасс,
`NumericalFormat`), gzip + base64 в `binaryContent`. Из формата Mathcad записываются выражения, пределы осей,
цвет и тип линии трасс; точность воспроизведения проверена на реальных файлах: дерево выражений
193 графиков корпуса пересоздаётся байт в байт для 165 (остальные 28 имеют другую шапку; различия остальных — битовые
флаги числовых листьев и «закрывающий» байт произведений, не влияющие на разбор). Остальное (сетка, логарифмы,
символы, легенда, заголовки, вторая ось Y, 3D, вид и палитра, полярные графики) хранится комментарием
`<!--xmath:region {json}-->` внутри `<region>`: Mathcad его пропускает, xmath при открытии берёт из него всю
область графика, если выражения и пределы в самом графике Mathcad не менялись. Рядом с графиком пишется `<rendering>`
(PNG, как нарисовала программа; `xmath_gui::print::render_plot_pngs`, масштаб 2×), для полярных и 3D графиков
это основное изображение (`<picture>`). Без картинок (CLI без GUI, `export_xmcd` ядра) полярный/3D график записывается
как текстовая область-заглушка с тем же комментарием. Настройки листа, которых нет в `.xmcd` точно
(`format`, `plot_defaults`, `page`), лежат в `<!--xmath:worksheet {json}-->`. Двойной дефис внутри JSON
экранируется (`-\u002d`).

API: `export_xmcd(ws)` / `export_xmcd_with(ws, &ExportOptions { renderings, rendering_scale, env, outputs })`.

Проверка: `crates/xmath-core/tests/xmcd_lossless.rs` — круг `.xmath → .xmcd → .xmath` для всех примеров
(модель равна с точностью до положений в пунктах; формулы сравниваются по каноническому виду), все поля
форматов графиков, устаревший комментарий, результаты (`--check`); на корпусе
(`XMCD_CORPUS=каталог cargo test --release -p xmath-core --test xmcd_lossless -- --ignored`) круг
`.xmcd → .xmcd` без различий вместе с графиками (кроме областей со случайными числами).

## Функции работы с файлами

Пути — от папки рабочего листа (CLI, MCP и GUI передают её; у несохранённого листа — от текущей папки).

| Запись | Действие |
|--------|----------|
| `M := READPRN("a.prn")` | числа через пробелы/запятые/«;», строка файла = строка матрицы; строки без чисел (заголовки) пропускаются |
| `WRITEPRN("a.prn") := M` | запись матрицы (определение особого вида, как в Mathcad); `APPENDPRN` дописывает |
| `READFILE("a.csv", "delimited")` / `READCSV("a.csv")` | разделитель (tab, `;`, `,`, пробел) определяется сам; заголовок пропускается; пустая ячейка = 0; `READFILE(f, "text")` — строка |
| `WRITECSV("a.csv") := M` | значения через запятую |
| `READEXCEL("a.xlsx", "Лист1!A1:C10")` | xlsx/xls/ods (calamine); диапазон `"A1:C10"`, `"Лист1"` или без аргумента (первый лист, заголовок пропускается); текст в явном диапазоне — ошибка |

Значения пишутся в СИ без единиц; комплексные не пишутся. Безопасность: чтение разрешено везде;
запись — только из явных определений `WRITEPRN(...) := …`, относительный путь не может выходить
из папки листа (`..` запрещено), абсолютный путь, написанный пользователем, разрешён; у листа без
папки запись относительных путей невозможна; MCP при вычислении вообще ничего не пишет.
В ядре: `Worksheet::evaluate_with(snapshots, &EvalEnv)`, `evaluate_worksheet_in(&ws, dir)`.

## Ссылки на другие листы

`Вставка → Ссылка…` (двойной щелчок по серой рамке `Ссылка: файл` меняет путь). Лист (`.xmath` или
`.xmcd`, путь от папки текущего) вычисляется первым, его определения видны в областях ниже ссылки.
Циклы и слишком глубокая вложенность дают ошибку. В `.xmcd` области `<reference>` импортируются
как ссылки (путь из `<link href>`).
